M1 BASELINE
Schema is v39: M1's v38 foundation tables plus additive app-owned
notification_preferences.system_notifications_enabled. Event global default
remains PlannerPreferences.defaultReminderMinutes; Task default remains
NotificationPreferences.defaultTaskReminderMinutes. Android permission is not
persisted. Custom reminder uses _CustomReminderDialog State ownership: one
TextEditingController, created once and disposed once by dialog State.

FOUNDATION SEAMS
NotificationGateway.schedule/cancel/pending is the only platform scheduling
contract. FlutterLocalNotificationsGateway uses zonedSchedule in UTC with
inexactAllowWhileIdle. NotificationPayloadCodec is typed, versioned and ID-only.
NotificationResponseController owns cold/warm capture. NotificationFoundation-
Repository owns ReminderPolicy persistence, sanitized BackgroundWorkRequest
persistence, and durable platform-ID allocation. No additional table is needed
for M2/M3.

EVENT SEAMS
CalendarEventRepository owns canonical saveEvent/editEvent/cancelEvent/
rescheduleEvent. CalendarEventController wraps those post-persistence writes
and is the authorized reconciliation entry seam. Recurrence/exception/
reschedule identity is CalendarEventOccurrence and CalendarEventOccurrence-
Identity.forDate. Existing IANA conversion is in calendar_event_time_zones.dart.
All-day Events lack an explicit canonical reminder time and must not be given
invented M2 notifications. Existing data layer already represents cancelled and
rescheduled occurrence lifecycle state.

TASK SEAMS
PlannerRepository.saveTask and PlannerController are canonical Task writes.
PlannerTask carries profile ID, dueDate, dueMinute, recurrence and status.
Timed Task eligibility requires dueDate + dueMinute + incomplete state. Date-
only Task has no dueMinute and must have no invented timed notification.
